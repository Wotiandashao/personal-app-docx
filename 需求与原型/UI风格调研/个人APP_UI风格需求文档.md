# 个人 APP UI 风格需求文档

版本：视觉提案 1.0  
调研日期：2026 年 9 月 21 日  
适用对象：`需求与原型/v1.0.0` 中的五页原型及离线交互原型  
提案名称：**蓝调独立志**  
状态：供视觉评审与后续原型修改使用；尚未替换 v1.0.0。

本方案以刺猬乐队官网的深蓝背景、蓝白对比、符号化标题和唱片封面陈列为视觉来源，将现有个人 APP 调整为带有早期个人网站与独立音乐刊物气质的移动界面。保留首页、点餐、选餐、待办、我的五页的信息结构和业务规则，重点改变色彩、排版、边框、图像容器与交互状态的视觉表达。

### 1.2 风格判断

“复古个人网站 + 独立摇滚刊物 + 少量拼贴元素”是本次设计归纳，**不是原站公布的设计体系名称**。它的识别度来自具体组合：大面积蓝色、有纹理的外壳，纸白内容区域，粗体标题与符号混排，以及紧密排列的图像。单纯把现有按钮改成深蓝，无法形成相同气质。

| 原站特征 | 可见或实测依据 | 迁移到 APP 的方式 |
| --- | --- | --- |
| 深蓝外壳 | body 底色 `#191F49`，叠加背景图片；实际观感受图片影响 | 深蓝页头、外侧细边与底部导航；采用本地可绘制的轻纹理 |
| 蓝底浅字标题条 | 首页栏目标题背景 `#000080`，文字 `#FFFAFA`，字重 700，实测字号 30px，圆角 4px | 保留对比关系；手机栏目字号缩至 18–21px |
| 纸白内容与粗虚线边缘 | 内容区背景 `#FFFAFA`，边框为 `9px dashed #000080` | 用顶部 8px 蓝白间隔条建立识别，内容框改为 1–1.5px 深蓝线 |
| 混排标题 | 导航中出现星号、音符、笑脸和不同字符组合；正文使用 Verdana 等字体栈 | 中文完整表达功能，星号等仅作装饰，英文作为次级刊物标签 |
| 封面陈列 | 方形专辑封面密集排列，局部配合黑色背景 | 餐品使用方形或接近方形的“封面框”，保留真实食物图 |
| 个性化点色 | 黄色、红色、绿色、粉色等小面积符号 | 收敛为黄色选中态、粉色装饰；危险操作单独用深红 |
| 模块化浏览 | 多栏目并列、模块标题和折叠入口 | 手机改为单列阅读；不新增现有原型没有的折叠逻辑 |

### 1.3 设计取舍

保留蓝白对比、纸张边缘、粗体标题、少量符号、封面式图像与轻微错位的装饰。APP 的列表、输入框和按钮保持对齐，不随装饰旋转；所有重要入口都有中文文字或明确的无障碍标签。

原站桌面多列结构、细小文本、大量外链、浮动二维码、持续变化的装饰和超宽内容不迁入 APP。乐队名称、标志、专辑封面和原站背景图只作为调研参考，交付效果图采用本项目餐品图、原创排版及 CSS 装饰。

## 3 整体视觉要求

### 3.1 设计方向

**UIR-01 识别度**：五页必须共享深蓝外壳、纸白主体、蓝白边缘和同一导航样式。首页在一眼内能识别“今日待办”和“下一餐”，装饰不占据主要阅读顺序。

**UIR-02 信息优先级**：页面标题 > 栏目标题 > 任务或食物名称 > 时间与辅助标签 > 装饰英文。重要信息不可只靠英文、颜色或图形表达。

**UIR-03 视觉密度**：减少原型中过大的空白和厚重软阴影，改为清楚的边框与紧凑分组。每个屏幕保留适量空白，不把所有区域做成海报。

**UIR-04 装饰强度**：单页至多 1–2 处醒目的贴纸或星号；旋转控制在约 ±8°，限于装饰。纹理仅用于背景和页头，不覆盖任务、手机号和输入内容。无闪烁、跑马灯或持续旋转。

### 3.2 配色变量

“来源”用于区分原站实测与移动端设计建议；建议值以本提案效果图为当前评审基准。

| 变量 | 值 | 用途 | 来源 |
| --- | --- | --- | --- |
| `--blue` | `#000080` | 栏目条、主操作、主导航、选中日期 | 原站实测 |
| `--night` | `#20296C` | 页头与外壳底色 | 根据原站背景观感制定的建议值 |
| `--paper` | `#FFFAFA` | 内容表面、蓝底文字 | 原站实测 |
| `--ink` | `#111333` | 正文、深色标签文字 | 原站 body 文字色实测 |
| `--yellow` | `#F4E44C` | 当前导航、当前上下文、少量标记 | APP 建议值 |
| `--pink` | `#EC77AC` | 非交互贴纸、装饰符号 | APP 建议值 |
| `--muted` | `#62627A` | 日期、辅助文字、完成任务文字 | APP 建议值 |
| `--line` | `#CDCCD7` | 分隔线 | APP 建议值 |
| `--danger` | `#A92748` | 删除和退出确认等危险操作 | APP 建议值 |

黄色底使用 `--ink` 或 `--blue` 文字，禁止白字；粉色底使用 `--ink`。蓝底使用纸白或黄色。完成态以勾选和删除线共同表达，不依赖绿色。装饰粉色不用于错误提示。

### 3.3 字体与排版

| 层级 | 建议字号与字重 | 行高与用途 |
| --- | --- | --- |
| 页面标题 | 36–40px，800–900 | 1.2；中文标题，保持水平 |
| 栏目标题 | 18–21px，700–800 | 1.3–1.4 |
| 正文与任务 | 16px，400–500 | 1.5；允许长标题换行 |
| 选餐名称 | 15–16px，700 | 1.5；至少可显示两行 |
| 三列餐品名称 | 13–14px，700 | 1.5；窄屏换行，不与相邻列重叠 |
| 元信息与导航 | 12–13px，400–700 | 1.4；保持清晰对比 |
| 纯装饰英文 | 10–11px，700 | 仅用于非必要信息，不承载操作含义 |

中文采用系统黑体，例如 Microsoft YaHei、PingFang SC；英文大字采用 Arial 的粗体；日期和版号可用 Consolas 等等宽字体。全部设置本地回退，不依赖在线字体。避免在正文中用不常见字符替换汉字或字母。

### 3.4 尺寸与布局

以 390 × 844 为效果图基准，同时适配 360、390、430px。桌面单页预览居中，手机主体最大 430px；产品界面不出现横向滚动。

- 页头：常规约 130–150px，不含系统状态栏；字放大或短屏时允许自适应高度。
- 外侧蓝边：约 10px；纸白内容内边距约 14–16px；顶端蓝白间隔装饰高 8px。
- 模块间距：16–26px；列表项主要触区高 56–64px；间距以 4px 为基础单位。
- 内容边框：1–1.5px；分隔线 1px；小阴影采用 2–4px 偏移和低透明度，减少柔化悬浮感。
- 容器以直角或 2–4px 小圆角为主；复选框和头像允许圆形。
- 底栏：内容触区不少于 56px，另加底部安全区；内容滚动区域不能被底栏遮挡。
- 普通按钮有效点击区至少 44 × 44px。七列日历在 360px 下每格可缩至约 40px 宽、高度至少 44px，格间不得重叠。
- 200% 字号或短屏可纵向滚动；不得通过缩小必要文字或隐藏内容来硬塞首屏。

效果图中的 9:41 和底部手势条用于说明手机画板。真实 APP 使用系统状态栏与系统手势区域，不重复绘制；网页原型中可按预览需要展示或省略。

## 4 组件需求

| 编号 | 组件 | 视觉与操作要求 |
| --- | --- | --- |
| C-01 | 页头 | 深蓝轻纹理；中文粗体标题；辅助英文；可附一枚原创符号，不能覆盖标题 |
| C-02 | 栏目与内容框 | 蓝底纸白标题条或独立中文标题；纸白背景、深蓝细边；标题右侧数量保持可读 |
| C-03 | 任务行 | 左侧圆形勾选，外部热区 44px；正文在右；完成态实心蓝勾与删除线；长标题换行 |
| C-04 | 餐品缩略图 | 方形或近方形边框，统一尺寸与内距；食物主体完整；名称位于图片外；不可把旧截图中的删除按钮裁进图片 |
| C-05 | 添加与修改 | 添加为蓝底纸白加号，44px；修改为黄底深字；编辑时显示“完成”并为每条记录显示删除入口 |
| C-06 | 分类栏 | 选中项蓝底白字、黄色底线；未选中深字；文字与内容同时更新，不能只变色 |
| C-07 | 日期单元格 | 普通深色数字；选中蓝底浅字和黄色底线；今天但未选中可用细描边，不能与选中态混淆 |
| C-08 | 输入框 | 纸白底、蓝色细边；输入文字不少于16px；聚焦有明确边框或轮廓；错误附中文提示 |
| C-09 | 底部导航 | 顺序固定；蓝底浅色线性图标；选中黄底蓝图标及中文；保持单个选中项 |
| C-10 | 用户信息 | 纸白证件式布局、虚线分隔；头像可做双层描边；手机号完整脱敏显示 |
| C-11 | 退出确认弹窗 | 纸白矩形弹窗、深蓝边框；“取消”与深红危险操作区分；遮罩下背景不滚动 |
| C-12 | Toast | 深蓝底浅字，勾号或提示文字；出现在底栏上方，不挡主要按钮；读屏可感知 |

图标统一使用本地 SVG 或 CSS 绘制，避免依赖彩色 emoji 的平台差异。纯装饰设置 `aria-hidden`；图标按钮提供中文名称；焦点轮廓应与背景有明显反差。

按钮按下可产生 1px 位移或轻微明暗变化，时间约 100–160ms；状态切换约 150–200ms。不改变可点击区域，不依赖 hover，不添加音效。减少动态效果设置下关闭非必要动画。

## 5 五页改造要求

### 5.1 首页

对应效果图：`效果图/01-首页.png`。

页头用大字“首页”、黄色星号与小贴纸建立风格。下方保持“今日待办 → 下一餐”的顺序。待办采用蓝色栏目条，右上显示剩余数量；两条摘要使用清楚的行分隔，“查看全部”始终可见。

下一餐仍显示“午餐 12:00”，食物排为三张封面式缩略图。整块摘要进入点餐页，不能给单张图片增加未定义的详情功能。日期是视觉辅助；实际原型应取设备当天日期，效果图固定为 2026-09-21。

没有待办时显示“今天没有待办”，保留查看全部入口；午餐为空时显示现有空摘要文案并保留进入点餐入口。

### 5.2 点餐

对应效果图：`效果图/02-点餐.png`。

早餐、午餐、晚餐顺序保持。每个餐次用编号和中文标题组织，添加按钮放在对应餐次标题右侧，缩短寻找距离。三列餐品保留相同视觉尺寸，超过三条时换行，整页可滚动。

右上“修改”为黄色文字按钮。进入编辑态后改为“完成”，每条餐品显示深红删除按钮，有明确“删除某餐品”标签与足够热区；不得只展示一个无法点击的小红点。相同食物的重复记录必须分别显示、分别删除。

效果图中三杯牛奶是现有演示数据，不应去重。空餐次保留标题和添加按钮，显示“暂未添加餐品”。

### 5.3 选餐

对应效果图：`效果图/03-选餐.png`。

页头提供返回点餐；顶端黄色条显示“当前将加入 · ×餐”。左侧固定五分类，右侧是图像、名称、添加按钮构成的列表。隐藏四项主导航，避免离开子流程时丢失上下文。

餐品图像统一边框。较长食物名称允许两行。当前分类通过蓝色块、白字和黄色底线表达。增加食物后显示“已加入×餐”，停留在页面且允许连续添加；不要增加结算条或购物车。

效果图展示主食，包括米饭、全麦面包、燕麦粥和面条。水果分类保持“暂无可选水果”，不能为填充视觉而创造业务数据。

### 5.4 待办

对应效果图：`效果图/04-待办.png`。

月历采用“蓝色月份栏 + 纸白日期网格”，七列对齐且周日为首列。选中日期为深蓝实底和黄色底线。示例为 2026 年 9 月，1 日位于周二，21 日位于周一。

日历下保持输入框与加号，再展示选中日期的任务列表。任务完成态使用勾选与删除线，保留恢复能力。不得因为图形风格而新增任务优先级或拖动排序。

六行月份、长任务、大字体和键盘弹出时允许内容纵向滚动。提交按钮、焦点输入框及列表最后一项不能被底栏或键盘永久遮挡。

### 5.5 我的

对应效果图：`效果图/05-我的.png`。

资料区采用纸质证件式布局，用小面积胶带形装饰和虚线分隔；昵称与脱敏手机号沿用现有内容。效果图中的“满”字圆形头像为**可替换的设计占位**，后续可换回原头像并保留双圈边框；不代表新增头像编辑能力。

退出登录为深红描边按钮，点击进入既有确认流程。下方英文海报字只用于空白区域的视觉表达；在短屏或放大字体时可缩减或隐藏此装饰。不要添加设置、会员、统计等入口。

## 6 状态覆盖要求

五张主效果图展示默认或选中状态。下表定义后续原型必须补齐的状态，不把未展示的状态误认为已制作完毕。

| 场景 | 文案与视觉 | 功能要求 |
| --- | --- | --- |
| 待办全部完成 | 纸白内容框内居中“今天没有待办”；不显示无效勾选框 | 查看全部继续可用 |
| 无任务日期 | “暂无任务”，输入入口仍可用 | 新任务加入选中日期 |
| 完成任务 | 实心蓝勾，标题删除线和弱化文字 | 再次点击恢复；首页联动不变 |
| 空输入提交 | 输入框深红边与“请输入任务内容”提示 | 聚焦输入框，不新增任务 |
| 空餐次 | 虚线分组内“暂未添加餐品”，保留蓝色添加按钮 | 进入对应餐次选餐 |
| 水果无数据 | “暂无可选水果”，无假餐品和添加按钮 | 可切换其他分类 |
| 添加成功 | 蓝底浅字 Toast“已加入×餐” | 不导航；重复添加仍可用 |
| 删除餐品 | 编辑态出现深红删除入口，删除后重新排列 | 只删指定 itemId |
| 退出弹窗 | 中文标题、取消、确认退出；深红只用于危险操作 | 取消、遮罩、Esc 与确认四种路径保持 |
| 图片缺失 | 稳定尺寸的浅色占位和食物名称 | 图片失败不挤压按钮，不阻断操作 |
| 加载或存储异常 | 延续现有离线原型的处理，不新增虚构加载流程 | 若未来接服务端，再单独补充加载与重试需求 |
