## 2. 范围与目标

### 2.1 实施目标

在不改变 v1.0.0 业务范围、数据模型和核心交互规则的前提下，将当前浅灰背景、白色大圆角卡片和亮蓝强调色的交互原型，改造成 UI 风格调研中定义的“蓝调独立志”视觉：深蓝页头与底栏、纸白内容区、蓝白边缘、粗体中文标题、少量黄色和粉色装饰、唱片封面式餐品排布。

完成后，v1.0.0 内部的可交互原型、五张静态原型图和 PRD 附录截图应保持一致；首页、点餐、选餐、待办、我的五页原有功能及跨页面数据联动应通过回归验证。

## 4. 推荐实施方案

### 4.1 方案概述

采用“保留业务内核，替换展示层”的方案：

1. 先在 `index.html` 建立统一页头、纸白内容区、页面辅助标签和装饰节点，保留所有现有 ID、页面 `data-page` 和表单/弹窗语义。
2. 在 `app.js` 中只调整动态 HTML 模板和状态属性，使餐次编号、分类选中态、任务状态、导航状态和动态日期可由 CSS 稳定表达；数据和事件流程保持不变。
3. 在 `styles.css` 中建立新设计变量和共用组件，再逐页校准。页面使用深蓝外壳与页头、纸白内容区、1–1.5px 深蓝边框、黄色选中态和低强度粉色装饰。
4. 从现有本地原型图提取九种餐品与头像为独立图片，摆脱整页截图的固定背景坐标；水果继续保持无数据状态。
5. 完成所有功能态和响应式回归后，再导出五张正式原型图，并同步交互原型参考图和 PRD 附录，确保同一版本只有一套最终视觉。

业务数据流保持为：用户操作 → 更新现有 `state` → `saveData` → `renderLinkedViews` 或当前页渲染 → Toast/页面状态反馈。视觉改造不引入第二套状态管理。

### 4.2 关键决策

| 决策 | 选择 | 理由 | 替代方案及不采用原因 |
| --- | --- | --- | --- |
| 代码改造方式 | 在现有三个文件上定向改造，不另建新原型 | 当前原型功能完整且业务逻辑集中；可减少双版本漂移 | 复制整套”新版原型”会产生两个 v1.0.0 真源，并增加后续同步成本 |
| 视觉结构 | HTML 提供稳定语义结构，CSS 负责纹理、边缘与装饰 | 可避免用伪元素承载必要文字，也能保持可访问性 | 全部通过 CSS 覆盖无法可靠表达动态日期、餐次编号和目标餐次提示 |
| 动态代码范围 | 只调整渲染模板、展示格式和 ARIA 状态 | 新 UI 的动态列表需要新类和状态属性，但业务规则无需改变 | 完全不改 JS 会迫使 CSS 依赖脆弱的元素顺序；重写 JS 则风险过大 |
| 餐品与头像素材 | 从现有本地原型图提取为独立 PNG 文件，保留现有头像，并保留源参考图 | 已验证提取质量可行；避免背景位置随尺寸变化；UI 风格文档明确”满”字为占位 | 继续裁切整页截图会让新原型依赖旧 UI；使用远程图片违反离线要求；”满”字头像需额外设计工作 |
| 背景纹理 | 使用 CSS 渐变和低透明度重复纹理 | 离线、可缩放、无品牌素材风险 | 直接复用参考站背景图不适合本项目，也增加外部素材依赖 |
| 装饰英文 | 保留为非必要辅助文字，必要时短屏隐藏 | 能传达风格但不影响中文任务完成 | 用英文替换中文标题会降低可用性；完全取消会削弱效果图识别度 |
| 底部导航 | 保留按钮与事件绑定，改为蓝底、黄色选中块 | 不改变路由和交互，满足 `C-09` | 改成链接或新路由没有业务收益并可能影响 Hash 行为 |
| 静态图与 PRD 同步时机 | 所有交互和响应式回归通过后一次性更新 | 避免测试期间截图反复失效 | 边开发边替换 PRD 会造成重复工作和中间版本不一致 |
| 静态图尺寸 | 780×1688 二倍图（纵横比保持 390×844） | 提升 PRD 嵌入图清晰度，适合文档归档和打印 | 390×844 一倍图文件小但 PRD 中清晰度不足；更高分辨率增加文件体积且收益有限 |
| PRD 同步工具 | 编写 Python-docx 脚本自动替换 media 文件并验证渲染 | 可自动化、可重复执行、减少手工错误；脚本可复用于后续版本同步 | 手工替换 DOCX 内部文件易出错且难以验证；LibreOffice 批处理脚本对 Windows 环境支持不稳定 |
| 执行拆分 | 两份执行计划：原型实现；验收与版本产物同步 | 两阶段有清晰依赖和独立交付边界，PRD 同步必须等待原型定稿 | 单份计划会把 DOCX 与截图更新混入实现过程，不利于回退和验收 |

### 4.4 接口与数据变化

无外部接口、服务端接口、存储结构或数据迁移。

- `STORAGE_KEY` 保持 `personalAppPrototype.v1`。
- `meals`、`tasksByDate`、`profile`、`targetMeal`、`selectedCategory`、`mealEditMode` 等状态字段保持原结构和语义。

- 新增的 DOM 节点（动态日期、英文副标题、装饰元素）只承载视觉辅助信息，不写入 localStorage。
- 动态日期由 `formatDate()` 等辅助函数在渲染时从 `new Date()` 或状态中的日期对象生成，首页显示设备当天，待办页显示选中日期。
- `aria-current`、`aria-pressed`、`aria-hidden` 等属性属于展示与可访问状态，不参与业务数据。

### 4.5 关键流程、异常与边界

1. **应用初始化**：加载默认数据并合并合法本地数据，进入 Hash 指定页面或首页；新页头与背景不影响原初始化顺序；首页渲染时调用 `formatDate(new Date())` 填充动态日期节点。
2. **首页**：显示设备当天日期（格式如"2026-09-21"和"周一"，通过 `formatDate` 和 `formatWeekday` 生成）、未完成任务计数与前两条、固定午餐 12:00 与前三项；完成任务后继续从首页移除并同步待办页。
3. **点餐**：三餐以编号标题和封面式网格呈现；修改/完成切换保留；编辑态每条记录显示独立深红删除入口；添加按钮仍写入正确 `targetMeal`。
4. **选餐**：黄色目标条由 `targetMeal` 动态输出；左侧唯一分类选中；添加后仍停留并显示 Toast；直接进入时继续兜底午餐；水果保持空状态，显示"暂无可选水果"，采用纸白背景、居中灰色文字，不显示任何添加按钮或占位图。
5. **待办**：日历月首与天数算法不变；选中日期通过蓝底与黄色底线表示；输入、空输入错误、完成与恢复及首页联动不变；长任务由单行截断改为允许换行，但仍保存最多 50 字符。
6. **我的**：保留小满、脱敏手机号和现有头像（用户决策：不使用"满"字占位头像）；装饰海报在短屏或大字体时通过媒体查询降级（缩小或隐藏）；退出弹窗保留取消、遮罩、Esc、确认四条路径和焦点恢复。
7. **导航**：主页面只高亮一个底栏项并同步 `aria-current`；选餐隐藏底栏；底栏不能遮挡内容底部。
8. **素材缺失**：餐品图或头像加载失败时保留固定容器、中文名称和操作，使用纸白/浅灰占位，不导致布局收缩。
9. **存储异常**：继续静默保留内存状态，不因新视觉增加网络或错误页。
10. **长内容与小屏**：三列餐品名称和选餐长名称可换行；六行月份、50 字符任务、200% 文字及 360×640 短屏允许纵向滚动，重要按钮可达。
11. **减少动态效果**：`prefers-reduced-motion: reduce` 下关闭页面进入、弹窗、Toast 和错误摇动等非必要动画，状态仍即时可见。

## 附录 A：PRD 图片替换脚本示例

```python
#!/usr/bin/env python3
"""
PRD 图片替换脚本
功能：自动替换 DOCX 文档中附录 A 的五张原型图（image1.png 至 image5.png）
依赖：python-docx（pip install python-docx）
用法：python replace_prd_images.py <docx路径> <新图目录>
"""

import sys
import os
import shutil
from datetime import datetime
from docx import Document
from docx.opc.constants import RELATIONSHIP_TYPE as RT

def replace_images(docx_path, new_images_dir, backup=True):
    """
    替换 DOCX 中的图片
    
    Args:
        docx_path: DOCX 文件路径
        new_images_dir: 新图片目录，应包含 01-首页.png 至 05-我的.png
        backup: 是否备份原文件
    """
    # 备份原文件
    if backup:
        backup_path = f"{docx_path}.backup.{datetime.now().strftime('%Y%m%d_%H%M%S')}"
        shutil.copy2(docx_path, backup_path)
        print(f"✓ 已备份原文件到: {backup_path}")
    
    # 加载文档
    doc = Document(docx_path)
    
    # 图片映射关系：DOCX media 文件名 -> 新图片文件名
    image_mapping = {
        'image1.png': '01-首页.png',
        'image2.png': '02-点餐.png',
        'image3.png': '03-选餐.png',
        'image4.png': '04-待办.png',
        'image5.png': '05-我的.png'
    }
    
    replaced_count = 0
    
    # 遍历文档的所有图片关系
    for rel in doc.part.rels.values():
        if "image" in rel.target_ref:
            old_image_name = os.path.basename(rel.target_ref)
            
            # 检查是否是需要替换的图片
            if old_image_name in image_mapping:
                new_image_name = image_mapping[old_image_name]
                new_image_path = os.path.join(new_images_dir, new_image_name)
                
                if not os.path.exists(new_image_path):
                    print(f"✗ 警告：新图片不存在: {new_image_path}")
                    continue
                
                # 读取新图片
                with open(new_image_path, 'rb') as f:
                    new_image_data = f.read()
                
                # 获取旧图片信息
                old_size = len(rel.target_part.blob)
                old_dims = f"{len(rel.target_part.blob)} bytes"
                
                # 替换图片数据
                rel.target_part._blob = new_image_data
                
                new_size = len(new_image_data)
                print(f"✓ 已替换 {old_image_name} -> {new_image_name}")
                print(f"  旧图大小: {old_size} bytes, 新图大小: {new_size} bytes")
                
                replaced_count += 1
    
    # 保存文档
    doc.save(docx_path)
    print(f"\n✓ 替换完成，共替换 {replaced_count} 张图片")
    print(f"✓ 已保存到: {docx_path}")
    
    return replaced_count

def main():
    if len(sys.argv) < 3:
        print("用法: python replace_prd_images.py <docx路径> <新图目录>")
        print("示例: python replace_prd_images.py ../../v1.0.0/v1.0.0_个人APP产品需求文档_PRD.docx ../../v1.0.0/原型/原型图")
        sys.exit(1)
    
    docx_path = sys.argv[1]
    new_images_dir = sys.argv[2]
    
    if not os.path.exists(docx_path):
        print(f"错误：DOCX 文件不存在: {docx_path}")
        sys.exit(1)
    
    if not os.path.exists(new_images_dir):
        print(f"错误：新图片目录不存在: {new_images_dir}")
        sys.exit(1)
    
    print("PRD 图片替换脚本")
    print("=" * 60)
    print(f"DOCX 文件: {docx_path}")
    print(f"新图目录: {new_images_dir}")
    print("=" * 60)
    print()
    
    replace_images(docx_path, new_images_dir)

if __name__ == '__main__':
    main()
```

**使用说明**：

1. 安装依赖：`pip install python-docx`
2. 将脚本保存到 `TEMP/v1.0.0-docx-scripts/replace_prd_images.py`
3. 在执行计划 02 中，导出五张 780×1688 静态图后运行：
   ```bash

   python replace_prd_images.py "../../需求与原型/v1.0.0/v1.0.0_个人APP产品需求文档_PRD.docx" "../../需求与原型/v1.0.0/原型/原型图"
   ```
4. 打开替换后的 DOCX 检查图片清晰度和分页

## 附录 D：装饰元素实现规范

装饰元素（星号、贴纸、海报文字）的技术实现和可访问性标准：

### D.1 实现技术

**HTML 结构**：
```html
<!-- 装饰元素使用 span + CSS 定位和变换实现 -->
<span class="decor decor-star" aria-hidden="true">★</span>
<span class="decor decor-sticker" aria-hidden="true">
  <img src="assets/decor/sticker-meal.svg" alt="">
</span>
<span class="decor decor-poster-text" aria-hidden="true">DAILY PLAN</span>
```

**CSS 定位**：
```css
.decor {
  position: absolute;
  pointer-events: none; /* 不影响点击和焦点 */
  user-select: none; /* 不可选中 */
}

.decor-star {
  top: 20px;
  right: 30px;
  font-size: 24px;
  color: var(--pink);
  opacity: 0.8;
  transform: rotate(-15deg);
}
```

**响应式降级**：
```css
/* 短屏或小字体下缩小装饰 */
@media (max-height: 700px) {
  .decor-star {
    transform: scale(0.7) rotate(-15deg);
  }
}

/* 极小屏幕隐藏装饰 */
@media (max-height: 600px) {
  .decor {
    display: none;
  }
}
```

### D.2 可访问性要求

1. **所有装饰元素必须标记 `aria-hidden="true"`**，对屏幕阅读器隐藏
2. **纯视觉装饰不使用背景图片**，避免加载失败影响布局
3. **装饰色不参与对比度要求**，因为已标记为 `aria-hidden`
4. **装饰元素不得遮挡或干扰交互元素**，使用 `pointer-events: none`
5. **装饰元素的文字内容为纯英文或符号**，不传达必要信息

### D.3 短屏降级策略

| 视口高度 | 降级策略 | 保留元素 |
| --- | --- | --- |
| ≥ 844px | 完整显示所有装饰 | 全部 |
| 700-843px | 装饰缩小 70% | 全部 |
| 600-699px | 装饰缩小 50% | 仅星号和关键贴纸 |
| < 600px | 隐藏所有装饰 | 无 |

**验证方法**：
- 在 360×640、390×700、390×844、430×932 视口下截图
- 检查装饰元素是否按降级策略显示
- 验证隐藏装饰后内容仍完整可用
