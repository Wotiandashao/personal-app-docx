## 2. 目标与边界

### 2.1 目标

对改造后的交互原型执行完整回归和质量验收。只有 P0 检查通过后，才导出 780×1688 的五张正式原型图、同步交互原型参考图，并通过可重复的 Python-docx 脚本更新 PRD 附录 A。最终确保交互原型、静态图、参考图和 PRD 嵌入图属于同一视觉版本，且业务规则没有变化。

### 2.2 包含内容

- PRD AT-01 至 AT-14、状态边界、响应式、键盘、ARIA、对比度、200% 字号、减少动效及离线验证。
- 以 390×844 视口、二倍像素导出五张 780×1688 PNG。
- 覆盖 `原型/原型图` 五张正式图，并同步 `原型/交互原型/assets/reference` 的对应副本。
- 创建和运行 `TEMP/v1.0.0-docx-scripts/replace_prd_images.py`，替换 PRD 附录 A 的五张媒体图片。
- 在 PRD 修订记录增加“视觉原型更新，业务规则未变”，不调整产品版本号。
- 使用 `render_docx.py` 完整渲染并逐页检查，完成最终文件和 TEMP 清理核对。

### 2.3 不包含内容

- 不扩大交互原型的业务范围，不修改存储结构、默认数据、Hash 和核心规则。
- 不在 P0 回归通过前覆盖正式静态图、参考图或 PRD。
- 不手工改写 PRD 正文业务条款，不改变产品版本号。
- 不自动提交、合并 `feature/ui-redesign-v1.0.0` 或创建 `v1.0.0-ui-redesign` 标签。

## 3. 成功标准

- PRD AT-01 至 AT-14 全部完成，P0 全通过，P1 无阻塞性失败；每项有真实结果和证据。
- 五页在目标视口、200% 字号、键盘和减少动效下可用，必要颜色对比度达标。
- 正式五图均为 780×1688，无浏览器外壳、滚动条、调试提示或临时状态。
- 正式图与 `assets/reference` 对应副本逐文件哈希一致，PRD 嵌入的五图内容对应一致。
- PRD 完整渲染后无裁切、重叠、缺字、异常空白或意外正文变化。
