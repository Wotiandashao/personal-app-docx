## 4. 推荐实施方案

### 4.1 总体方案与视觉决策

采用“原有 DOM 与模板定向调整 + 统一 CSS”的方案。页面仍由 Hash 路由切换，动态内容继续由当前渲染函数生成。仅变更展示层及其引用，不改业务状态流。

| 决策 | 推荐选择 | 理由与约束 |
| --- | --- | --- |
| 视觉依据 | 最新 PNG 为主，风格参考为补充 | 最新首页和主页面标题实际较大，不能机械采用文档建议的 22–24px 而明显偏离最新图 |
| 设计参数 | 背景 `#F0F1F6`，表面 `#FFFFFF`，主字 `#141414`，辅助字 `#787B82`，分隔 `#E4E6EC`，强调 `#D13745` | 来自风格文档的建议值；最新图片有细微颜色变化，采用统一色值，不逐像素复制生成噪点 |
| 字体 | 全局沿用现有 `:root` 系统中文无衬线字体栈（`"Microsoft YaHei", "PingFang SC", "Noto Sans CJK SC", Arial, sans-serif`）；删除局部 `Consolas, monospace` 与 `Arial` 覆盖，日历数字、手机号同样使用该字体栈 | 最新五图无等宽或装饰字体；现有局部覆盖属于旧杂志风格 |
| 尺寸起点 | 在 390×844 逻辑视口校准：主页面标题建议约 36px，栏目约 20px，正文 14–16px，辅助信息 12–13px；普通圆角约 8px | 属于方案起点，需按图片缩放后的可见比例复核；不能声称这些值是图片源码参数 |
| 间距起点 | 外卡左右约 14–16px、标题左右约 18–20px、卡内 12–16px；模块间 24–32px | 对应最新图片中标题、卡片与图片的对齐关系；保留 4/8/12/16/24/32 间距体系 |
| 页面实现 | 原生页面保持可交互，复用独立照片 | 不采用整页 PNG 作背景或绝对定位热点，避免数据变化后视觉失效 |
| 行为与日期 | 保留真实运行日期、现有午餐展示及业务逻辑 | 图中样例数据不能触发业务范围扩展；截图验收另行控制测试数据与时间 |
| 旧装饰 | 删除目标结构或伪元素中的英文、贴纸、星形、条纹、编号和海报 | 对 JS 仍有读取的展示节点必须同步调整；不只依靠隐藏保留失效绑定 |

普通卡片无阴影、无粗边框；浅白主导航使用细顶分隔，仅当前图标与文字变红。原有导航 SVG 可局部调整路径以贴近最新图，不更换整套图标库。焦点、完成态和危险操作需保持可辨识，不以浅色设计牺牲可用性。
